# Council question (Phase 4) — ActionProof

ActionProof is an evidence-verified safety gate between AI agents and tools. USP: "Proof before permission" — G1: no value can authorize a write unless its derivation re-checks; G2: no approval can be replayed. Built so far: prepare/commit protocol with signed one-use receipts, OPA policy (AP-VER-01 verification, AP-SCOPE-02 on_behalf_of scope, AP-CUM-03 cumulative cap 5000.00 per actor+vendor re-checked inside the commit transaction, AP-INV-04 variance > 100 => REVIEW), taint rule (text from documents cannot fill an authority field unless DIRECT-verified at the cited page/box or equal to the system of record), Postgres one-use constraints, red-team-tested. Hero demo: approve invoice INV-2048 ($4,800 vs PO $4,300, $500 unexplained) => REVIEW; a human then mints a one-use review token. The final product has a review console (roles submitter/reviewer/admin, server-side sessions) and a 3-minute demo video. A hackathon judging panel (CodeQuest 2026) will see it. Prototype scope: mock services only, no real payments.

## Question 1
When a decision is REVIEW, a human mints a one-use token bound to the request hash. Must that human be DIFFERENT from the submitting party? Identities available: `actor` (the software agent, e.g. agent-7), `on_behalf_of` (the human or team the agent acts for, e.g. user-123), and the reviewer's console login. Options: (A) reviewer must differ from both actor and on_behalf_of, enforced in the gate (four-eyes), violation = DENY with a rule id; (B) reviewer may be anyone with the reviewer role, audited; (C) configurable per tool/threshold. Cost of being wrong: self-approval would let one compromised or careless person undo the REVIEW control the product exists to provide; over-strictness blocks solo operators in a prototype.

## Question 2
A second connector will be built end to end through the same gate. Which better shows BOTH taint AND cumulative limits in a 3-minute demo: (A) vendor bank-detail change (new bank account for a vendor, with a "bank change letter" PDF that could carry injected or forged text), or (B) refund (refund amount for a customer against an original payment, with a refund-request PDF and cumulative refund caps per actor+customer)? The connector will be built either way; this only picks which one. Judging is by a panel watching a 3-minute demo plus the repo.
